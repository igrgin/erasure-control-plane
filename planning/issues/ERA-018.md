# ERA-018: Complete adapter deduplication and checkpoint recovery

Epic: [EPIC-05](../epics/EPIC-05.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

Each demonstrator safely reports or resumes an approved operation after an interruption.

## Requirements and dependencies

Requirements: REQ-07, REQ-08.

Depends on: [ERA-017](ERA-017.md), [ERA-011](ERA-011.md).

## Intended implementation ownership

- `adapters/transactional/`
- `adapters/events/`
- `contracts/`
- `tests/adapter-recovery/`

## Acceptance criteria

- [ ] Transactional adapter commits cleanup with its operation receipt in one source transaction.
- [ ] Chunked adapter persists approved selection/checkpoints and makes each chunk safely repeatable.
- [ ] Duplicate commands return the same operation state; a reused key with different content is rejected.
- [ ] Define operation-ledger retention longer than retry/restore windows and a status lookup that does not claim deletion verification.

## Verification

Crash before/after commit and between chunks, replay commands, and tamper with a reused key; query synthetic stores and retained operation ledgers.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
