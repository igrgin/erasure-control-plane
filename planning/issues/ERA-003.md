# ERA-003: Approve and execute the first proposal with durable evidence

Epic: [EPIC-01](../epics/EPIC-01.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

A source owner approves one proposal and sees the adapter-reported cleanup result.

## Requirements and dependencies

Requirements: REQ-06, REQ-07, REQ-08, REQ-11.

Depends on: [ERA-002](ERA-002.md).

## Intended implementation ownership

- `backend/proposals-decisions/`
- `backend/execution/`
- `backend/audit/`
- `adapters/transactional/`
- `frontend/review/`

## Acceptance criteria

- [ ] Check tenant grant and source ownership; approval binds the exact plan digest and versions.
- [ ] Commit approval, audit, and queued command atomically; execution survives a control-plane restart.
- [ ] Use a stable operation key; transactional source cleanup and its receipt commit together, and duplicate delivery returns the original result.
- [ ] Record attempts and adapter-reported receipt; the UI describes success without independent verification claims.

## Verification

Run the full cleanup on synthetic records, duplicate the command, and restart after approval; assert one effective cleanup and attributable audit history.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
