# ERA-019: Expose partial, failed, and unknown execution outcomes

Epic: [EPIC-05](../epics/EPIC-05.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

An operator can tell a known failure from partial work or an operation whose effects are uncertain.

## Requirements and dependencies

Requirements: REQ-08, REQ-10, REQ-11.

Depends on: [ERA-017](ERA-017.md), [ERA-018](ERA-018.md).

## Intended implementation ownership

- `backend/execution/`
- `backend/cases/`
- `frontend/execution/`

## Acceptance criteria

- [ ] Classify pre-execution rejection, retryable transport failure, partial effects, terminal failure, and unknown outcome separately.
- [ ] A lost response uses status reconciliation with the existing operation key; no blind new destructive operation.
- [ ] Bound retry/backoff and require owner/operator intervention when adapter history cannot resolve uncertainty.
- [ ] Show attempts, checkpoints, residual impact, next actor, and available safe actions in the UI.

## Verification

Drop a successful response, exhaust the retry budget, lose the adapter ledger in a fixture, and inject partial results; verify outcomes and blocked unsafe retry.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
