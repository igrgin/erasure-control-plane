# ERA-017: Run durable leased workers with bounded source and tenant concurrency

Epic: [EPIC-05](../epics/EPIC-05.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

More than one worker can make progress without duplicating effective cleanup or starving unrelated work.

## Requirements and dependencies

Requirements: REQ-08, REQ-14.

Depends on: [ERA-004](ERA-004.md).

## Intended implementation ownership

- `backend/execution/`
- `tests/concurrency/`

## Acceptance criteria

- [ ] Claim indexed jobs in short transactions, attach lease/fencing tokens, and recover expired leases.
- [ ] Never hold a database lock during source/network work; stale workers cannot update current state.
- [ ] Bound retries and apply per-source/tenant concurrency, fair scheduling, and source circuit-breaker behavior.
- [ ] Keep stable operation IDs across delivery retries and record every attempt.

## Verification

Run two workers, terminate a lease holder, deliver a late stale result, and saturate one source; verify fencing and unrelated-source progress.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.
