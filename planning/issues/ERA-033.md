# ERA-033: Generate repeatable inventory and workflow scale workloads

Epic: [EPIC-09](../epics/EPIC-09.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

The project owner can reproduce load that reflects accounts, sources, buckets, and revision churn.

## Requirements and dependencies

Requirements: REQ-03, REQ-14.

Depends on: [ERA-007](ERA-007.md), [ERA-004](ERA-004.md).

## Intended implementation ownership

- `tests/load/`
- `docs/benchmarks/`

## Acceptance criteria

- [ ] Seed smoke, normal, and storage-focused tiers with documented sparse/dense distribution and bounded history.
- [ ] Build workloads against accepted protocol fixtures and the initial adapter; include all three real adapters in final measurements after ERA-039, and label simulated additional source identities.
- [ ] Model reads, summary refreshes, approvals, exports, failures, and a large-account hotspot.
- [ ] Record environment, seed, bucket horizon, retention, concurrency, candidate, and provisional target values.

## Verification

Run a reproducibility smoke test and confirm expected row counts and workload mix before collecting throughput evidence.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.
