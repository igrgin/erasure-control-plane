# ERA-007: Ingest tenant inventory with revisions, completeness, and resync

Epic: [EPIC-02](../epics/EPIC-02.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

Adapters can report account data amounts reliably without sending raw records.

## Requirements and dependencies

Requirements: REQ-03, REQ-12.

Depends on: [ERA-006](ERA-006.md).

## Intended implementation ownership

- `backend/inventory/`
- `contracts/`
- `adapters/`
- `tests/inventory/`

## Acceptance criteria

- [ ] Accept bounded batches with publication ID, stream revision, bucket bounds, category/measure/unit, observation time, and coverage.
- [ ] Duplicate publications are harmless; out-of-order revisions cannot overwrite newer inventory.
- [ ] Support explicit empty observations, authoritative bucket replacement, tombstones, and full resync.
- [ ] Enforce adapter tenant/source scope, payload limits, and backpressure; persist ingestion acknowledgments.

## Verification

Test duplicate/reordered batches, an interrupted resync, retention tombstones, wrong-tenant payloads, and oversized batches with real PostgreSQL.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
