# ERA-023: Close requests with explicit coverage and acknowledged exceptions

Epic: [EPIC-06](../epics/EPIC-06.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

An operator can close a request with a defensible account of every registered source in its scope.

## Requirements and dependencies

Requirements: REQ-04, REQ-10, REQ-11.

Depends on: [ERA-021](ERA-021.md), [ERA-022](ERA-022.md), [ERA-009](ERA-009.md).

## Intended implementation ownership

- `backend/cases/`
- `frontend/closure/`

## Acceptance criteria

- [ ] Require a disposition for every snapshotted source before closure.
- [ ] Distinguish completed, closed-with-exceptions, and cancelled aggregate outcomes.
- [ ] Unknown/retained/rejected outcomes require an explicit exception reason and accountable acknowledgment.
- [ ] Show unregistered-source limits, backup/archive exclusions, and adapter-reporting limits; closure is not legal certification.

## Verification

Attempt premature closure, close with retained/unknown exceptions, and close a healthy case; verify no missing source and no independently-verified claim.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
