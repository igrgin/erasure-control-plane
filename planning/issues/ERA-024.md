# ERA-024: Demonstrate complete customer-request scenarios

Epic: [EPIC-06](../epics/EPIC-06.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

The project owner can demonstrate healthy cleanup and realistic exception handling from intake to closure.

## Requirements and dependencies

Requirements: REQ-04, REQ-07, REQ-09, REQ-10, REQ-11.

Depends on: [ERA-023](ERA-023.md), [ERA-012](ERA-012.md), [ERA-015](ERA-015.md), [ERA-019](ERA-019.md).

## Intended implementation ownership

- `tests/e2e/`
- `docs/walkthrough/`

## Acceptance criteria

- [ ] Include externally received customer request references and employee-only access.
- [ ] Cover healthy deletion/transformation, no matching data, retention hold, owner rejection, unavailable source, and unknown outcome.
- [ ] Show hourly/daily summaries and precise/coarse request rules in the same walkthrough.
- [ ] Record owner UAT for each scenario against the candidate and preserve fixture expectations.

## Verification

Run browser journeys through intake, review, execution/intervention, closure, and timeline for each scenario.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
