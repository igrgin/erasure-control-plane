# ERA-034: Prove isolation and recovery with multiple API and worker instances

Epic: [EPIC-09](../epics/EPIC-09.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

The demonstration preserves authorization and workflow semantics when replicas increase.

## Requirements and dependencies

Requirements: REQ-08, REQ-12, REQ-14.

Depends on: [ERA-033](ERA-033.md), [ERA-017](ERA-017.md), [ERA-029](ERA-029.md).

## Intended implementation ownership

- `deploy/scale-demo/`
- `tests/concurrency/`
- `backend/accounts-access/`
- `backend/execution/`

## Acceptance criteria

- [ ] Run at least two API instances and two workers against shared PostgreSQL/session storage.
- [ ] Prove pooled-connection tenant context cannot leak between requests/jobs; test actual runtime row policies.
- [ ] Kill an API/worker during owner decisions and dispatch; retain one valid decision and safe operation identity.
- [ ] Demonstrate per-tenant/source authorization for adapter batches, exports, and recovery jobs.

## Verification

Execute concurrent multi-tenant browser/API traffic with instance termination, overlapping requests, and stale-worker responses.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.
