# ERA-012: Review a multi-source request and its time/retention differences

Epic: [EPIC-03](../epics/EPIC-03.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

An operator and source owners can understand one request spanning heterogeneous sources.

## Requirements and dependencies

Requirements: REQ-03, REQ-04, REQ-05, REQ-09.

Depends on: [ERA-010](ERA-010.md), [ERA-011](ERA-011.md), [ERA-008](ERA-008.md).

## Intended implementation ownership

- `frontend/requests/`
- `frontend/review/`
- `tests/e2e/`

## Acceptance criteria

- [ ] Show inventory context separately from fresh proposal counts and their observation time.
- [ ] Present each source action, executable interval, retention exclusions, estimate units, and blockers side by side.
- [ ] Show unsupported boundaries and whole-account/expanded scope prominently before decisions.
- [ ] Retain partial progress when another source cannot propose; source failures do not overwrite other results.

## Verification

Walk through a two-source request containing a supported precise interval, a daily-boundary mismatch, and a retained subset.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
