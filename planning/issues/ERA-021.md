# ERA-021: Define per-source disposition and request closure transitions

Epic: [EPIC-06](../epics/EPIC-06.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

Every source in a request has a visible disposition and a clear transition path.

## Requirements and dependencies

Requirements: REQ-10, REQ-11.

Depends on: [ERA-004](ERA-004.md).

## Intended implementation ownership

- `backend/cases/`
- `frontend/requests/`

## Acceptance criteria

- [ ] Separate current source state, individual attempts, and final disposition.
- [ ] Represent no-data, reported completion, partial, retained, rejected, failed, unknown, unavailable, and cancelled cases.
- [ ] Specify allowable transitions and authorization; completed history cannot be overwritten by a retry.
- [ ] Derive aggregate progress without treating exceptions as successful cleanup.

## Verification

Test the state-transition matrix using the accepted status contract and baseline adapter, then integrate actual heterogeneous outcomes in ERA-024; verify each scoped source remains visible through every transition.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.
