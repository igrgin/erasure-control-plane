# ERA-013: Enforce source-owner authority and concurrent decisions

Epic: [EPIC-04](../epics/EPIC-04.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

Only an authorized accountable owner can decide a proposal, including during concurrent review.

## Requirements and dependencies

Requirements: REQ-06, REQ-12.

Depends on: [ERA-005](ERA-005.md).

## Intended implementation ownership

- `backend/proposals-decisions/`
- `backend/accounts-access/`
- `frontend/review/`

## Acceptance criteria

- [ ] Require both employee tenant grant and current source-owner assignment for approval/rejection.
- [ ] Use optimistic decision versions so simultaneous contradictory decisions cannot both commit.
- [ ] Require a reason for rejection and record actor/time/source ownership evidence for each decision.
- [ ] Apply identical rules to direct API calls and UI; an auditor cannot mutate decisions.

## Verification

Race two owner decisions and test unrelated owners, revoked groups, auditors, forged tenant context, and valid scoped ownership.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
