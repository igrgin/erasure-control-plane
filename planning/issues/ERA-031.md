# ERA-031: Prove safe backup, restore, credential rotation, and rollback

Epic: [EPIC-08](../epics/EPIC-08.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

The project owner can recover the demonstration without replaying destructive operations from stale state.

## Requirements and dependencies

Requirements: REQ-08, REQ-13.

Depends on: [ERA-030](ERA-030.md), [ERA-018](ERA-018.md).

## Intended implementation ownership

- `deploy/operations/`
- `docs/runbooks/`
- `tests/recovery/`

## Acceptance criteria

- [ ] Back up control-plane state, identity configuration, and adapter ledgers; record restore order and protected access.
- [ ] Restore into isolation with dispatch paused, then reconcile stable operation keys before resuming.
- [ ] Exercise adapter/database credential rotation and compatible image rollback; cleanup itself is never rolled back.
- [ ] Measure proposed RPO/RTO and preserve results; an absent adapter ledger blocks automatic recovery.

## Verification

Execute backup/restore and rollback drills against a case that already had effects but lost its response; assert no second uncontrolled cleanup.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
