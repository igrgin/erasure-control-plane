# ERA-025: Harden attributable audit events and evidence retention

Epic: [EPIC-07](../epics/EPIC-07.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

An auditor can reconstruct decisions and effects without collecting unnecessary source data.

## Requirements and dependencies

Requirements: REQ-11, REQ-12.

Depends on: [ERA-004](ERA-004.md).

## Intended implementation ownership

- `backend/audit/`
- `backend/cases/`
- `backend/execution/`

## Acceptance criteria

- [ ] Persist actor, tenant/source, request/proposal/version, decision, attempt, timestamp, correlation, and receipt provenance.
- [ ] Runtime roles cannot update/delete audit rows; privilege and retention administration are distinct.
- [ ] Avoid raw records, credentials, and arbitrary sensitive adapter payloads in audit/logs.
- [ ] Define separate retention for audit, inventory, request payloads, and adapter dedupe; document access and archival responsibility.

## Verification

Test mutation denial with runtime roles, event completeness for the baseline and contract fixtures, then integrate all real transitions in ERA-028, redaction fixtures, and recovery-ledger retention constraints.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.
