# ERA-029: Package the application topology for a clean HTTPS deployment

Epic: [EPIC-08](../epics/EPIC-08.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

The project owner can deploy the baseline application onto a single Linux host and extend it as source adapters become available.

## Requirements and dependencies

Requirements: REQ-13.

Depends on: [ERA-004](ERA-004.md).

## Intended implementation ownership

- `deploy/`
- `backend/config/`
- `frontend/config/`
- `adapters/config/`

## Acceptance criteria

- [ ] Provide local and deployment Compose configuration for proxy/frontend, API, worker, identity, database, and the baseline adapter/store; support adding separately configured adapter/store instances. Integrate the second adapter during EPIC-08 release acceptance.
- [ ] Keep source stores private to adapters; inject secrets and bind trusted endpoints explicitly.
- [ ] Run API and workers as separate profiles of immutable artifacts; supply readiness and shutdown behavior.
- [ ] Document prerequisites, synthetic seeding, persistent volumes, TLS/domain configuration, and resource envelope.

## Verification

Deploy to a clean target, exercise login and cleanup over HTTPS, inspect network exposure, and restart each service without losing durable work.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
