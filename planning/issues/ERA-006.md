# ERA-006: Publish versioned time, retention, and account-mapping capabilities

Epic: [EPIC-02](../epics/EPIC-02.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

An operator can see how a source identifies accounts and interprets its data time range.

## Requirements and dependencies

Requirements: REQ-01, REQ-02, REQ-09.

Depends on: [ERA-005](ERA-005.md).

## Intended implementation ownership

- `backend/source-registry/`
- `backend/accounts-access/`
- `contracts/`
- `adapters/`

## Acceptance criteria

- [ ] Define time field/semantics, bucket alignment, selection precision, cleanup methods, category retention, hold support, and limits.
- [ ] Version source-local account mappings and reject ambiguous or missing mappings without guessing.
- [ ] Validate protocol/capability compatibility and present unsupported capabilities explicitly.
- [ ] Changes produce new versions and preserve prior versions referenced by existing proposals.

## Verification

Contract-test hourly/exact and daily/calendar-day sources, ambiguous account mappings, unsupported protocol versions, and policy updates.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
