# ERA-009: Capture immutable request scope and precise time boundaries

Epic: [EPIC-03](../epics/EPIC-03.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

An operator can record a customer request whose account, interval, and source coverage stay unambiguous.

## Requirements and dependencies

Requirements: REQ-04, REQ-09.

Depends on: [ERA-006](ERA-006.md).

## Intended implementation ownership

- `backend/cases/`
- `frontend/requests/`
- `tests/time/`

## Acceptance criteria

- [ ] Record external request reference/reason and explicit UTC second-precision half-open boundaries; the UI shows normalization.
- [ ] Convert calendar dates using the selected time zone and handle daylight-saving gaps/overlaps explicitly.
- [ ] Snapshot source IDs/capability versions and report omitted, disabled, or unmapped registered sources as coverage exceptions.
- [ ] Editing the target account or interval creates a new request revision and invalidates affected proposals/decisions.

## Verification

Test exact boundary records, daylight-saving days, invalid intervals, added/disabled sources after creation, and request-scope revisions.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
