# ERA-016: Serialize overlapping cleanup and define cancellation races

Epic: [EPIC-04](../epics/EPIC-04.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

Operators can withdraw queued work and understand overlapping requests without unsafe execution races.

## Requirements and dependencies

Requirements: REQ-04, REQ-06, REQ-08.

Depends on: [ERA-014](ERA-014.md), [ERA-015](ERA-015.md).

## Intended implementation ownership

- `backend/cases/`
- `backend/execution/`
- `frontend/requests/`

## Acceptance criteria

- [ ] Serialize execution for overlapping tenant/source requests using durable coordination.
- [ ] After a prior operation finishes, require fresh precondition validation before the next operation runs.
- [ ] Withdrawal before dispatch prevents new effects; cancellation after dispatch is best effort with an explicit outcome.
- [ ] Document that source cleanup has no cross-source rollback and never report cancellation as undo.

## Verification

Race approval/withdrawal/dispatch and overlapping requests; assert valid serialization, clear UI states, and retained attempts.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
