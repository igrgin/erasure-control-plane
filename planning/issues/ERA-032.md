# ERA-032: Accept the deployed end-to-end release candidate

Epic: [EPIC-08](../epics/EPIC-08.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

The project owner can review a complete deployed candidate before final scale acceptance.

## Requirements and dependencies

Requirements: REQ-01, REQ-02, REQ-03, REQ-04, REQ-05, REQ-06, REQ-07, REQ-08, REQ-09, REQ-10, REQ-11, REQ-12, REQ-13, REQ-15.

Depends on: [ERA-031](ERA-031.md), [ERA-024](ERA-024.md), [ERA-026](ERA-026.md), [ERA-027](ERA-027.md), [ERA-028](ERA-028.md), [ERA-040](ERA-040.md).

## Intended implementation ownership

- `docs/release/`
- `docs/walkthrough/`
- `tests/e2e/`

## Acceptance criteria

- [ ] Run the full acceptance walkthrough with two tenants and all three required sources on the actual target.
- [ ] Attach deployed revision/image digests, test results, UAT, recovery evidence, and known limitations.
- [ ] Confirm employee-only operation, registered-source coverage limits, and no independent deletion verification.
- [ ] Record open risks and operational owner; do not call the full first release complete before EPIC-09 scale evidence and EPIC-10 public-demo acceptance.

## Verification

Perform attended UAT on the deployed candidate and rerun only failed or changed scenarios after repair.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
