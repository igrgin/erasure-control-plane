# ERA-020: Prove recovery with a deterministic cross-process failure harness

Epic: [EPIC-05](../epics/EPIC-05.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

The project owner can reproduce difficult failure cases and inspect their evidence.

## Requirements and dependencies

Requirements: REQ-08, REQ-12, REQ-14.

Depends on: [ERA-019](ERA-019.md), [ERA-016](ERA-016.md).

## Intended implementation ownership

- `tests/failure/`
- `tests/e2e/`
- `docs/verification/`

## Acceptance criteria

- [ ] Provide deterministic process termination, delayed/duplicate commands, response loss, and source-outage scenarios.
- [ ] Cover approval-to-enqueue atomicity, execution/receipt gaps, expired leases, and independent source progress.
- [ ] Assert tenant/source isolation and effective cleanup counts in fixture stores.
- [ ] Retain scenario seed, candidate revision, logs without sensitive payloads, and pass/fail evidence.

## Verification

Run the documented failure matrix on actual API/worker/adapter processes with PostgreSQL, not only mocked adapter responses.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
