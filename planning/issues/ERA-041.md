# ERA-041: Assess demo hosting, recurring cost, and resource viability

Epic: [EPIC-10](../epics/EPIC-10.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

The project owner can choose whether and where a public demo is worth hosting.

Requirements: REQ-13, REQ-15.

Depends on: [ERA-037](ERA-037.md).

## Acceptance criteria

- [ ] Compare a single paid VM, paid managed multi-service hosting, and static/recorded presentation using dated official documentation and pricing.
- [ ] Estimate full-stack CPU/RAM/storage and itemize compute, domain, backups, storage, tax, and traffic; label estimates separately from measured application capacity.
- [ ] Document region, persistent storage, TLS/identity routes, uptime mode, maintenance/reset, monitoring, and teardown requirements; explain relevant free-tier limitations.
- [ ] Record a conditional hosting recommendation and owner budget/provider decision; require measured full-stack validation before launch.
- [ ] If live hosting cannot meet the resource/budget constraints, record the blocker and fallback; static visibility alone does not satisfy a live-demo requirement without a scope revision.

## Verification

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.
