# ERA-001: Bootstrap employee login and isolated business accounts

Epic: [EPIC-01](../epics/EPIC-01.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

An employee can log in and select only business accounts they are authorized to operate.

## Requirements and dependencies

Requirements: REQ-01, REQ-12.

Depends on: [ERA-037](ERA-037.md).

## Intended implementation ownership

- `backend/accounts-access/`
- `frontend/`
- `deploy/local/`

## Acceptance criteria

- [ ] Pin supported Java/Spring Boot, React, database, and tool versions; document local run commands.
- [ ] Seed two tenants and explicit employee grants; authenticated tenant selection cannot expand those grants.
- [ ] Use PostgreSQL runtime row policies and composite tenant keys; the migration role is distinct from runtime.
- [ ] Display the selected business account consistently and reject unauthorized reads and writes.

## Verification

Run real-PostgreSQL authorization tests using the runtime role and browser login/account-selection checks, including overlapping source-local IDs.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
