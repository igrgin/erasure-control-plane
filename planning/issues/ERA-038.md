# ERA-038: Create the three-store environment and deterministic synthetic fixtures

Epic: [EPIC-10](../epics/EPIC-10.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

A developer can start and populate relational, document, and cache sources without the full control plane.

## Requirements and dependencies

Requirements: REQ-01, REQ-03, REQ-09, REQ-13, REQ-15.

Depends on: [ERA-037](ERA-037.md).

- `demo/sources/`

## Acceptance criteria

- [ ] Provide private container profiles for PostgreSQL, MongoDB, and Redis with pinned compatible versions, source schemas/indexes, and independent credentials.
- [ ] Generate fixtures from a versioned seed and explicit time anchor; include two tenants, overlapping local IDs, boundary records, empty/stale coverage, retention exceptions, and TTL entries.
- [ ] Produce expected summaries and expected cleanup/transformation outcomes, separating source time from observation time and expiry.
- [ ] Provide start/seed/inspect/reset commands and allowlisted demo targets; reset quiesces any attached workers and invalidates old run-generation commands before restoring source state.
- [ ] Document disk/memory requirements from source smoke checks; the completed application envelope is measured later before public launch.

## Verification

Boot the sources on a clean machine, seed twice with the same reference time, compare expectations, test TTL progression and cross-tenant separation, and exercise reset both standalone and with the application attached.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.
