# ERA-028: Exercise operational interventions and data-minimization policies

Epic: [EPIC-07](../epics/EPIC-07.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

The project owner can pause unsafe dispatch and manage evidence/storage without erasing accountability.

## Requirements and dependencies

Requirements: REQ-09, REQ-11, REQ-13.

Depends on: [ERA-026](ERA-026.md), [ERA-027](ERA-027.md), [ERA-022](ERA-022.md), [ERA-019](ERA-019.md).

## Intended implementation ownership

- `docs/runbooks/`
- `tests/operations/`
- `backend/operations/`

## Acceptance criteria

- [ ] Document pause/resume, source isolation, unknown-result escalation, inventory resync, and ledger-loss response.
- [ ] Exercise inventory retention/downsampling and audit archival rules without changing approved selection semantics.
- [ ] Ensure logs/exports/operational views do not expose raw fixture records or secrets.
- [ ] Name next actors and finite recovery exits; local alert simulation is distinguishable from real paging integration.

## Verification

Run intervention drills, audit all integrated workflow transitions, check retention boundaries and archive/readback, and redaction scans with documented candidate evidence.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
