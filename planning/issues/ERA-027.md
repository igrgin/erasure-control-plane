# ERA-027: Show operational health and actionable workflow metrics

Epic: [EPIC-07](../epics/EPIC-07.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

An internal operator can detect unavailable adapters, stale inventory, and stuck work.

## Requirements and dependencies

Requirements: REQ-03, REQ-08, REQ-13.

Depends on: [ERA-007](ERA-007.md), [ERA-017](ERA-017.md).

## Intended implementation ownership

- `backend/observability/`
- `frontend/operations/`
- `deploy/telemetry/`

## Acceptance criteria

- [ ] Measure ingest lag, coverage freshness, approval age, queue age, retries, unknown outcomes, and execution latency.
- [ ] Provide health/readiness checks that distinguish API availability from source availability.
- [ ] Use bounded metric labels; avoid tenant IDs and operation IDs as unbounded labels.
- [ ] Expose management views only to authorized staff and attach safe correlation IDs to logs.

## Verification

Inject outage and queue backlog; assert the dashboard/alerts change while unrelated requests continue and health endpoints reveal no credentials.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
