# ERA-005: Register sources and bind owners and adapter principals

Epic: [EPIC-02](../epics/EPIC-02.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

An administrator registers a company source and assigns its accountable owner and adapter access.

## Requirements and dependencies

Requirements: REQ-02, REQ-12.

Depends on: [ERA-004](ERA-004.md).

## Intended implementation ownership

- `backend/source-registry/`
- `frontend/sources/`
- `contracts/`

## Acceptance criteria

- [ ] Create/edit source metadata and owner groups through the UI; audit those changes.
- [ ] Bind each adapter principal to one source and an explicit allowed tenant scope.
- [ ] Revoke or rotate a principal without deleting historical decisions; unregistered or revoked principals cannot publish or consume commands.
- [ ] Distinguish administrator, operator, source-owner, auditor, and adapter permissions.

## Verification

Test registration, revocation, forged source IDs, tenant-scope violations, and owner-group changes across HTTP and stored commands.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
