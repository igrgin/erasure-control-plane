# ERA-015: Provide an owner review queue with explicit decisions and reasons

Epic: [EPIC-04](../epics/EPIC-04.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

A source owner can find pending work, inspect impact, and explain their decision.

## Requirements and dependencies

Requirements: REQ-05, REQ-06, REQ-11.

Depends on: [ERA-013](ERA-013.md).

## Intended implementation ownership

- `frontend/review/`
- `backend/proposals-decisions/`

## Acceptance criteria

- [ ] List only authorized tenant/source proposals with filters, pagination, age, and current version.
- [ ] Require viewing the actionable scope and estimate before confirmation; capture approval/rejection/revision-request decisions.
- [ ] Handle stale versions as a refresh/review action rather than silently applying the decision to a new proposal.
- [ ] Show decision history and the actor responsible for the next action; consume the baseline immutable-plan contract, then integrate expanded stale-plan checks from ERA-014 at epic acceptance.

## Verification

Browser-test valid approval, rejection reason, revision requests, concurrent stale views, and unauthorized queue access.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
