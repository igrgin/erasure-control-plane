# ERA-026: Deliver tenant-authorized audit timeline and export

Epic: [EPIC-07](../epics/EPIC-07.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

An auditor can inspect and export one request as readable decision evidence.

## Requirements and dependencies

Requirements: REQ-11, REQ-12.

Depends on: [ERA-025](ERA-025.md).

## Intended implementation ownership

- `frontend/audit/`
- `backend/audit/`
- `tests/exports/`

## Acceptance criteria

- [ ] Timeline links proposals, approval revisions, blockers, attempts, receipts, dispositions, and closure.
- [ ] Export includes source coverage, exclusion reasons, actor/time/version, and adapter-reported certainty.
- [ ] Paginate or stream large history; apply tenant/source access checks during export generation and retrieval.
- [ ] Escape untrusted source text and record export access without leaking another tenant through cached artifacts.

## Verification

Compare exported evidence with a known scenario history; test unauthorized retrieval, revoked access, malicious source strings, and large timelines.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
