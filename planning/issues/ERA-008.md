# ERA-008: Show business-account inventory and source coverage

Epic: [EPIC-02](../epics/EPIC-02.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

An operator can inspect the known data held for a business account and decide what to request.

## Requirements and dependencies

Requirements: REQ-02, REQ-03.

Depends on: [ERA-007](ERA-007.md).

## Intended implementation ownership

- `frontend/inventory/`
- `backend/inventory/`
- `backend/source-registry/`

## Acceptance criteria

- [ ] Display per-source amounts, units, bucket granularity, policy, observed time, and coverage bounds.
- [ ] Show fresh, stale, incomplete, no-data, disabled, and unavailable sources separately.
- [ ] Filter and paginate by time/source; never sum incompatible units or imply missing buckets mean zero.
- [ ] Link the account view into request creation and show that only registered sources are covered.

## Verification

Browser-test hourly/daily sources, stale and empty inventory, incompatible measures, pagination, and tenant switching without cached-data leakage.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
