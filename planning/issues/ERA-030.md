# ERA-030: Build immutable images and an approved promotion pipeline

Epic: [EPIC-08](../epics/EPIC-08.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

## Outcome

The project owner can promote an exact tested candidate with recorded image digests.

## Requirements and dependencies

Requirements: REQ-12, REQ-13.

Depends on: [ERA-029](ERA-029.md).

## Intended implementation ownership

- `.github/workflows/`
- `deploy/release/`
- `docs/release/`

## Acceptance criteria

- [ ] PR checks cover backend/database, frontend, adapter contracts, module boundaries, and selected end-to-end scenarios.
- [ ] Tagged builds produce pinned images and a candidate record with dependency inventory and test evidence.
- [ ] Use separate staging/demo configuration and a project-owner approval before remote deployment.
- [ ] Run migrations with a distinct role and smoke-test the same image digests after promotion; failed checks stop it.

## Verification

Perform a staging promotion rehearsal, force a failed smoke check, and confirm no unapproved promotion or secret leakage.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

## Boundaries

Use the [product requirements](../../docs/specification.md) and [architecture contract](../../docs/architecture.md). Operate on synthetic data for the demonstration. Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
