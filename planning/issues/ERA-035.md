Epic: [EPIC-09](../epics/EPIC-09.md). Milestone: v0.1 end-to-end demonstration. Status: proposed.

Delivery and acceptance owner: project owner. Source-behavior decisions also require the accountable source owner.

The project owner can explain observed limits and identify the next scaling bottleneck.

## Acceptance criteria

- [ ] Measure API p95, ingestion rate/lag, approval-to-command delay, queue age, source latency, storage/index size, CPU/I/O, and connection usage.
- [ ] Test provisional targets on a documented envelope and report failures rather than presenting targets as achieved.
- [ ] Saturate one source/account and prove bounded retries and progress for unrelated work.
- [ ] Inspect query plans and contention; make any tuning change with before/after evidence and affected regression checks.

## Verification

Run the normal/storage workloads and outage/hotspot scenarios; retain raw results, configuration, and a brief bottleneck analysis.

Retain commands/results and owner review against the exact candidate. Application checks are implemented with the issue; these are acceptance instructions, not claims that tests already exist.

Changes to an approved scope or operation require new review. External deployment and GitHub publication follow their own owner authorization.
